{\ttfamily \doxylink{classEventGroup}{Event\+Group}} is deliberately {\bfseries{both}} \doxylink{classObserver}{Observer} and \doxylink{classSubject}{Subject}\+: it hears notices from its parent (\doxylink{classObserver}{Observer} role) and re-\/broadcasts them to its own children (\doxylink{classSubject}{Subject} role). This is not a misuse of the pattern -- Composite answers "{}what does this group contain?"{} while \doxylink{classObserver}{Observer} answers "{}who does this group need to tell?"{}, and those are genuinely different questions with genuinely different collaborators (parent vs children) even though the same object participates in both.

{\ttfamily \doxylink{classEventControl}{Event\+Control}} is {\bfseries{not}} part of the Composite tree. It represents the control-\/room staff at the client/root boundary and is a concrete \doxylink{classSubject}{Subject}.

{\ttfamily \doxylink{classSubject}{Subject}} is abstract, but not because {\ttfamily attach()}/{\ttfamily detach()}/{\ttfamily notify()} are pure virtual -- they are ordinary virtual functions with a single, fully working, reusable implementation in {\ttfamily Subject.\+cpp} that every concrete \doxylink{classSubject}{Subject} inherits unchanged. What actually keeps {\ttfamily \doxylink{classSubject}{Subject}} abstract is {\ttfamily describe\+Subject()}, a pure virtual operation every concrete \doxylink{classSubject}{Subject} implements differently ({\ttfamily \doxylink{classEventControl}{Event\+Control}} returns something like {\ttfamily "{}\+Event\+Control\mbox{[}\+Tech\+Connect 2026\mbox{]}"{}}, {\ttfamily \doxylink{classEventGroup}{Event\+Group}} returns {\ttfamily "{}\+Event\+Group\mbox{[}\+Keynote Zone\mbox{]}"{}}, etc.), used in Event\+Flow\textquotesingle{}s status/log output. This mirrors the class notes\textquotesingle{} {\ttfamily Pit\+Stop} example, where {\ttfamily Pit\+Stop} already has complete implementations of {\ttfamily attach()}/{\ttfamily detach()}/{\ttfamily notify()} yet stays abstract purely because it also declares its own domain-\/specific operations ({\ttfamily tyre()}, {\ttfamily fuel()}, {\ttfamily set\+Car()}, {\ttfamily race()}) as pure virtual for {\ttfamily Ferrari\+Stop} to implement.\hypertarget{md_README_autotoc_md3}{}\doxysubsection{\texorpdfstring{Field ownership across the Component hierarchy}{Field ownership across the Component hierarchy}}\label{md_README_autotoc_md3}
{\ttfamily \doxylink{classEventComponent}{Event\+Component}} (the base of {\itshape both} {\ttfamily \doxylink{classEventGroup}{Event\+Group}} and {\ttfamily \doxylink{classEventUnit}{Event\+Unit}}) declares {\ttfamily name\+\_\+}, {\ttfamily is\+Open\+\_\+}, {\ttfamily start\+Time\+\_\+}/{\ttfamily end\+Time\+\_\+} and {\ttfamily current\+Attendance\+\_\+}/{\ttfamily capacity\+Threshold\+\_\+} -- every kind of {\ttfamily \doxylink{classEventComponent}{Event\+Component}}, Leaf or Composite, has a schedule and a capacity threshold, because {\ttfamily OPEN}, {\ttfamily CLOSE}, {\ttfamily CAPACITY\+\_\+\+ALERT} and {\ttfamily EVACUATE} are required to affect all of them uniformly. Only {\ttfamily \doxylink{classEventUnit}{Event\+Unit}} additionally declares {\ttfamily indoors\+\_\+} and {\ttfamily is\+Paused\+\_\+}, since "{}is this physically indoors"{} and "{}is this individual unit paused"{} are only ever meaningful for a single operational unit, never for a whole {\ttfamily \doxylink{classEventGroup}{Event\+Group}} (a zone doesn\textquotesingle{}t have a location relative to weather, and it doesn\textquotesingle{}t itself get "{}paused"{} -- only the leaves inside it do, individually). Two protected helpers on {\ttfamily \doxylink{classEventComponent}{Event\+Component}} -- {\ttfamily report\+Capacity\+Alert()} and {\ttfamily update\+Schedule()} -- hold the one shared implementation for the {\ttfamily CAPACITY\+\_\+\+ALERT}/{\ttfamily SCHEDULE\+\_\+\+CHANGE} reactions so that the many classes that need them don\textquotesingle{}t each re-\/implement the same comparison/print logic.\hypertarget{md_README_autotoc_md4}{}\doxysection{\texorpdfstring{3. Every {\ttfamily \doxylink{classSubject}{Subject}} can reach its observers two ways\+:


\begin{DoxyItemize}
\item {\bfseries{Cascaded}}, via {\ttfamily \doxylink{classEventControl_ac21db8f4791c306a2b214309b4e400e6}{Event\+Control\+::issue\+Notice()}} -\/\texorpdfstring{$>$}{>} {\ttfamily \doxylink{classSubject_ab5b0a79cd1214e08f11dbe18611e8f8c}{Subject\+::notify()}}, which broadcasts to every currently attached observer and, for any observer that is itself a {\ttfamily \doxylink{classSubject}{Subject}} (an {\ttfamily \doxylink{classEventGroup}{Event\+Group}}), continues cascading down through the whole subtree. \item {\bfseries{Targeted}}, via {\ttfamily Event\+Control\+::issue\+Direct\+Notice(target, notice)}, which delivers straight to one specific {\ttfamily \doxylink{classEventGroup}{Event\+Group}}/{\ttfamily \doxylink{classEventUnit}{Event\+Unit}}\textquotesingle{}s {\ttfamily update()}, bypassing {\ttfamily \doxylink{classEventControl}{Event\+Control}}\textquotesingle{}s own registration list. One consequence worth calling out\+: because {\ttfamily RESUME} is in the leaf-\/scoped group and {\ttfamily POWER\+\_\+\+OUTAGE} is not, a {\ttfamily \doxylink{classCateringStation}{Catering\+Station}}/ {\ttfamily \doxylink{classMedicalStation}{Medical\+Station}} that switches to its fallback mode during a {\ttfamily POWER\+\_\+\+OUTAGE} is {\bfseries{not}} reset by a later conference-\/wide {\ttfamily RESUME} -- that {\ttfamily RESUME} only reaches the four other leaf types. This is itself another instance of "{}same notice, different (in this case, no) reaction"{} driven purely by which classes have a {\ttfamily case} for it, not by any controller checking types (see {\ttfamily main.\+cpp}\textquotesingle{}s SD4 scenario).\hypertarget{md_README_autotoc_md7}{}\doxysubsection{\texorpdfstring{Capacity thresholds}{Capacity thresholds}}\label{md_README_autotoc_md7}
Every {\ttfamily \doxylink{classEventComponent}{Event\+Component}} -- leaf or group -- carries its own {\ttfamily current\+Attendance\+\_\+}/{\ttfamily capacity\+Threshold\+\_\+} pair (declared once in {\ttfamily \doxylink{classEventComponent}{Event\+Component}}, see "{}\+Field ownership"{} above), set via {\ttfamily set\+Current\+Attendance()}/{\ttfamily set\+Capacity\+Threshold()} (a simulated headcount feed -- not derived from any {\ttfamily \doxylink{structNotice}{Notice}}). When a {\ttfamily CAPACITY\+\_\+\+ALERT} arrives, the shared {\ttfamily \doxylink{classEventComponent_a9825b3edb52b95f7e7aa4264a025f1a8}{Event\+Component\+::report\+Capacity\+Alert()}} helper compares the two and logs either "{}\+VENUE FULL"{} or a "{}not yet full"{} status; it does nothing if {\ttfamily capacity\+Threshold\+\_\+} was never set (still -\/1). {\ttfamily get\+Capacity()} remains a {\itshape different} concept -- the recursive sum of every leaf\textquotesingle{}s fixed physical capacity -- so "{}how many seats exist"{} and "{}is it full right now"{} are tracked and reasoned about independently.\hypertarget{md_README_autotoc_md8}{}\doxysection{\texorpdfstring{4. Original features (\+Task 4.\+4)}{4. Original features (Task 4.4)}}\label{md_README_autotoc_md8}
Tech\+Connect\textquotesingle{}s three official original features are \texorpdfstring{$\ast$}{*}\texorpdfstring{$\ast$}{*}{\ttfamily POWER\+\_\+\+OUTAGE}\texorpdfstring{$\ast$}{*}\texorpdfstring{$\ast$}{*}, \texorpdfstring{$\ast$}{*}\texorpdfstring{$\ast$}{*}{\ttfamily CANCEL}\texorpdfstring{$\ast$}{*}\texorpdfstring{$\ast$}{*} and \texorpdfstring{$\ast$}{*}\texorpdfstring{$\ast$}{*}{\ttfamily ANNOUNCEMENT}\texorpdfstring{$\ast$}{*}\texorpdfstring{$\ast$}{*}. ({\ttfamily WEATHER\+\_\+\+ALERT} also exists as an extra notice type beyond the seven required by the specification and follows the same "{}add one small \`{}case\`{} per interested class"{} principle below, but is not counted among the three official answers to this task.) Each of the three is deliberately scoped to a small, already-\/existing subset of classes, so adding it only ever means adding one {\ttfamily case} to the relevant leaves\textquotesingle{}/{\ttfamily \doxylink{classEventGroup}{Event\+Group}}\textquotesingle{}s existing {\ttfamily react\+To\+Notice()} switch -- never a new base class, a new cross-\/cutting interface, or new responsibilities on {\ttfamily \doxylink{classEventControl}{Event\+Control}}. {\ttfamily \doxylink{classEventControl}{Event\+Control}} still only ever knows how to broadcast or target-\/deliver a {\ttfamily \doxylink{structNotice}{Notice}}; it never needs to know which concrete leaf types care about which notice type, which is what keeps it (and every other class) from growing into a god object as the notice list grows\+:


\begin{DoxyItemize}
\item \texorpdfstring{$\ast$}{*}\texorpdfstring{$\ast$}{*}{\ttfamily POWER\+\_\+\+OUTAGE}\texorpdfstring{$\ast$}{*}\texorpdfstring{$\ast$}{*} -- affects only {\ttfamily \doxylink{classCateringStation}{Catering\+Station}} and {\ttfamily \doxylink{classMedicalStation}{Medical\+Station}}. Every other leaf type\textquotesingle{}s {\ttfamily react\+To\+Notice()} simply never gained a {\ttfamily case} for it, so they fall through to their existing {\ttfamily default\+:} and stay completely unaffected; {\ttfamily \doxylink{classEventGroup}{Event\+Group}} needed no change at all, since it simply cascades every notice type it doesn\textquotesingle{}t specifically care about.
\item \texorpdfstring{$\ast$}{*}\texorpdfstring{$\ast$}{*}{\ttfamily CANCEL}\texorpdfstring{$\ast$}{*}\texorpdfstring{$\ast$}{*} -- affects {\ttfamily \doxylink{classLectureHall}{Lecture\+Hall}}, {\ttfamily \doxylink{classWorkshopRoom}{Workshop\+Room}}, {\ttfamily \doxylink{classRegistrationDesk}{Registration\+Desk}} and {\ttfamily \doxylink{classExhibitionBooth}{Exhibition\+Booth}} only, reusing the same {\ttfamily is\+Open\+\_\+} state and {\ttfamily default\+:} dispatch those four already had for {\ttfamily CLOSE}/{\ttfamily EVACUATE}; no new state was required anywhere, and {\ttfamily \doxylink{classMedicalStation}{Medical\+Station}}/{\ttfamily \doxylink{classCateringStation}{Catering\+Station}}/{\ttfamily \doxylink{classShuttleStop}{Shuttle\+Stop}}/{\ttfamily \doxylink{classEventGroup}{Event\+Group}} simply never gained a {\ttfamily case} for it.
\item \texorpdfstring{$\ast$}{*}\texorpdfstring{$\ast$}{*}{\ttfamily ANNOUNCEMENT}\texorpdfstring{$\ast$}{*}\texorpdfstring{$\ast$}{*} -- the opposite scoping to the other two\+: instead of touching several leaf types, it is handled {\itshape only} by {\ttfamily \doxylink{classEventGroup}{Event\+Group}} (one {\ttfamily case} in one class), since a PA-\/style announcement is inherently a property of an area, not of any individual unit inside it. No leaf type gained a {\ttfamily case}, a field, or any awareness that {\ttfamily ANNOUNCEMENT} exists at all -- it simply flows through their {\ttfamily update()}/{\ttfamily notify()} plumbing like any other notice they don\textquotesingle{}t specifically handle. This demonstrates the other end of the same principle as the two leaf-\/scoped features above\+: adding a notice never requires touching every class, only the (possibly very small) set of classes that actually care.
\end{DoxyItemize}\hypertarget{md_README_autotoc_md9}{}\doxysection{\texorpdfstring{5. Ownership policy}{5. Ownership policy}}\label{md_README_autotoc_md9}
This project does {\bfseries{not}} use {\ttfamily \texorpdfstring{$<$}{<}memory\texorpdfstring{$>$}{>}} or {\ttfamily \texorpdfstring{$<$}{<}algorithm\texorpdfstring{$>$}{>}} (by requirement), so ownership is entirely explicit rather than delegated to smart pointers, and list operations use hand-\/written loops instead of {\ttfamily std\+::find}/{\ttfamily std\+::remove}.


\begin{DoxyItemize}
\item {\bfseries{Composite ownership}}\+: {\ttfamily \doxylink{classEventGroup}{Event\+Group}} owns its children through a {\ttfamily std\+::vector\texorpdfstring{$<$}{<}Event\+Component\texorpdfstring{$\ast$}{*}\texorpdfstring{$>$}{>}}. {\ttfamily add()} and {\ttfamily remove\+Child()} together maintain the invariant that {\bfseries{every {\ttfamily \doxylink{classEventComponent}{Event\+Component}} is owned by at most one {\ttfamily \doxylink{classEventGroup}{Event\+Group}} at any moment}}\+: {\ttfamily add()} takes ownership of a freshly-\/created child or of a pointer just released by {\ttfamily remove\+Child()}; {\ttfamily remove\+Child()} hands ownership to the caller and removes it from {\ttfamily children\+\_\+} so the old owner will never {\ttfamily delete} it. {\ttfamily \texorpdfstring{$\sim$}{\string~}\+Event\+Group()} explicitly {\ttfamily delete}s every pointer still in {\ttfamily children\+\_\+}, recursively tearing down the whole subtree exactly once. Destroying the root ({\ttfamily delete root;} in {\ttfamily main.\+cpp}) therefore destroys the entire owned subtree exactly once, with no manual bookkeeping needed beyond that single invariant.
\item {\bfseries{\doxylink{classObserver}{Observer} registration}}\+: {\ttfamily \doxylink{classSubject}{Subject}} stores {\bfseries{non-\/owning}} raw {\ttfamily Observer\texorpdfstring{$\ast$}{*}} pointers in a {\ttfamily std\+::vector}, managed with hand-\/written linear search/erase ({\ttfamily \doxylink{classSubject_a0884bfe374d352c6488a1e40c84246c8}{Subject\+::attach}}/{\ttfamily detach}) rather than {\ttfamily std\+::find}/{\ttfamily std\+::remove}. Destroying a {\ttfamily \doxylink{classSubject}{Subject}} never deletes an observer, and destroying an {\ttfamily \doxylink{classObserver}{Observer}} never deletes a subject.
\item {\bfseries{Coupling of the two}}\+: {\ttfamily \doxylink{classEventGroup_a4c0f84ecca145a195c118c95507c0701}{Event\+Group\+::add()}} transfers Composite ownership of a child {\itshape and} automatically registers it as an observer of the new parent. {\ttfamily \doxylink{classEventGroup_abe700d722780eb0496cd28ad5822dedb}{Event\+Group\+::remove\+Child()}} reverses both in one call. This coupling is a deliberate design choice (anything physically inside a group should, by default, hear what affects that group) and is what makes runtime reorganisation (Task 4.\+2) a single, safe two-\/step operation\+: {\ttfamily parent-\/\texorpdfstring{$>$}{>}remove\+Child(x)} then {\ttfamily new\+Parent-\/\texorpdfstring{$>$}{>}add(x)}. If the pointer returned by {\ttfamily remove\+Child()} is not subsequently {\ttfamily add()}ed anywhere, the caller becomes responsible for {\ttfamily delete}-\/ing it themselves to avoid a leak -- {\ttfamily remove\+Child()} hands over {\itshape real} ownership, not just a view.
\item {\bfseries{Registrations independent of ownership are still possible}}\+: nothing stops a client from calling {\ttfamily subject.\+attach(observer)} directly for an object that subject does {\itshape not} own (see the {\ttfamily First Aid} double-\/registration in {\ttfamily main.\+cpp}), demonstrating that Composite ownership and \doxylink{classObserver}{Observer} registration are related but separate relationships in this design, and that an observer can register with more than one subject.
\end{DoxyItemize}\hypertarget{md_README_autotoc_md10}{}\doxysection{\texorpdfstring{6. Push vs pull}{6. Push vs pull}}\label{md_README_autotoc_md10}
Event\+Flow uses {\bfseries{push}}. {\ttfamily \doxylink{structNotice}{Notice}} carries everything an observer needs ({\ttfamily type}, {\ttfamily message}, an optional informational {\ttfamily capacity\+Threshold}, and {\ttfamily new\+Start\+Time}/{\ttfamily new\+End\+Time} for {\ttfamily SCHEDULE\+\_\+\+CHANGE}) and {\ttfamily \doxylink{classSubject_ab5b0a79cd1214e08f11dbe18611e8f8c}{Subject\+::notify()}}/{\ttfamily \doxylink{classObserver_a1facbbd0e34f6034d183ae9bcabbf1b0}{Observer\+::update()}} pass the {\ttfamily \doxylink{structNotice}{Notice}} directly. This was chosen because Tech\+Connect\textquotesingle{}s notices are inherently event-\/shaped (discrete occurrences, not continuously-\/polled state), so there is no meaningful "{}current subject state"{} for an observer to pull beyond the notice itself; push avoids observers needing a back-\/reference to their subject just to ask "{}what changed?"{}. Note that {\ttfamily CAPACITY\+\_\+\+ALERT} does {\itshape not} carry each object\textquotesingle{}s attendance figures in the {\ttfamily \doxylink{structNotice}{Notice}} -- those are tracked locally on every {\ttfamily \doxylink{classEventComponent}{Event\+Component}} via {\ttfamily set\+Current\+Attendance()}/{\ttfamily set\+Capacity\+Threshold()} (a simulated headcount feed, set independently of any notice) precisely because each object\textquotesingle{}s own occupancy is naturally {\itshape its} state, not the control centre\textquotesingle{}s to package and broadcast.\hypertarget{md_README_autotoc_md11}{}\doxysection{\texorpdfstring{7.
