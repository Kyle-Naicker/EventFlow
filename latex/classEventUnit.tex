\doxysubsection{Detailed Description}
Abstract base for every individual (non-\/composite) operational unit at Tech\+Connect\+: a leaf in the Composite tree. 

GoF roles\+:
\begin{DoxyItemize}
\item {\bfseries{Composite pattern}}\+: \doxylink{classEventUnit}{Event\+Unit} is a concrete {\bfseries{Leaf}}. It has no children and implements the component operations directly.
\item {\bfseries{\doxylink{classObserver}{Observer} pattern}}\+: \doxylink{classEventUnit}{Event\+Unit} is a concrete {\bfseries{\doxylink{classObserver}{Observer}}}. It is registered with the \doxylink{classEventGroup}{Event\+Group} that contains it and reacts to notices pushed down from above via \doxylink{classEventUnit_abfb9f5974cebf0330bfa0a4536b56174}{update()}.
\end{DoxyItemize}

These are two separate collaborations for two separate reasons\+: Composite asks "{}what does this unit consist of?"{} (answer\+: nothing, it is atomic) while \doxylink{classObserver}{Observer} asks "{}who does this unit need to hear from?"{} (answer\+: its containing \doxylink{classEventGroup}{Event\+Group}). Being both is not a pattern misuse -- see design rationale in README.\+md.

Concrete subclasses only need to implement \doxylink{classEventUnit_a896e33682a4c96fbcc970e807f5846bd}{react\+To\+Notice()} to get meaningfully different, polymorphic behaviour for the same notice -- no type-\/checking is used anywhere in the dispatch.

start\+Time\+\_\+/end\+Time\+\_\+/current\+Attendance\+\_\+/capacity\+Threshold\+\_\+/is\+Open\+\_\+ are all inherited directly from \doxylink{classEventComponent}{Event\+Component}. \doxylink{classEventUnit}{Event\+Unit} adds indoors\+\_\+ and is\+Paused\+\_\+, which are only ever meaningful for an individual operational unit (not for a whole \doxylink{classEventGroup}{Event\+Group}).
